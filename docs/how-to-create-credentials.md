# 認証情報の取得手順

Google Workspace を操作するためには、認証情報が必要です。
**OAuth クライアント**（利用者として認証）と**サービスアカウント**（ブラウザ認可が不要）のどちらかを用意します。

> **どの方式を使うかで、必要な作業が大きく変わります。先に [認証方式を選ぶ](#認証方式を選ぶ) を読んでください。**

---

## 認証方式を選ぶ

このサーバーは 2 種類の認証方式に対応しています。**やりたいことによって、必要な手間が大きく変わります。**

|                            | **OAuth（利用者として認証）**  | **サービスアカウント**                            |
| -------------------------- | ------------------------------ | ------------------------------------------------- |
| ブラウザでの認可           | 必要                           | **不要**                                          |
| OAuth 同意画面の設定       | 必要                           | **不要**                                          |
| Google の審査              | 組織外アカウントでは考慮が必要 | **不要**                                          |
| トークンの失効             | 設定によっては 7 日ごと        | **なし**                                          |
| **既存ファイルの読み書き** | ✅ その利用者の Drive 全体     | ✅ **共有したファイル・フォルダのみ**             |
| **新規ファイルの作成**     | ✅                             | ❌ **不可**（サービスアカウントは容量を持たない） |
| 露出範囲                   | Drive 全体                     | 共有した範囲だけ                                  |

**サービスアカウントを選ぶべきケース**

- 既存のスプレッドシートやドキュメントを読み書きしたい
- ブラウザでの認可や再認可をしたくない
- AI に見せる範囲を明示的に限定したい

→ [サービスアカウントを作成する](#サービスアカウントを作成する) へ

**OAuth を選ぶべきケース**

- 新しいスプレッドシートやプレゼンテーションを作らせたい
- Drive 全体を対象にしたい

→ [1. プロジェクト作成](#1-プロジェクト作成) へ。組織外のアカウントを使う場合は [どのプロジェクトで作るか](#どのプロジェクトで作るか) も必ず読んでください

---

## どのプロジェクトで作るか

OAuth 同意画面の **「対象」** の設定によって、そのプロジェクトの認証情報で認可できるアカウントが決まります。

| 対象   | 認可できるアカウント                                               |
| ------ | ------------------------------------------------------------------ |
| `内部` | そのプロジェクトが属する **Google Workspace 組織のアカウントのみ** |
| `外部` | 任意の Google アカウント（個人の Gmail アカウントを含む）          |

**組織外のアカウント（個人アカウントなど）を追加したい場合、`内部` のプロジェクトの認証情報は使えません。**
認可しようとすると「アクセスをブロック: ○○ は組織内でのみ利用可能です」と表示されます。

この場合は、**そのアカウントで新しい GCP プロジェクトを作成し、専用の `credentials.json` を用意してください。**
配置先は次のとおりで、共有の `credentials.json` より優先されます。

```
~/.google-workspace-mcp/
├── credentials.json                          # 共有（会社アカウント用など）
└── accounts/
    └── private/
        └── credentials.json                  # このアカウント専用
```

> **会社所有のプロジェクトを `外部` に変更して使い回すことは推奨しません。**
> 会社の OAuth アプリを任意の Google アカウントから使える状態にすることになり、組織ポリシーで禁止されている場合もあります。

## 1. プロジェクト作成

[Google Cloud Console](https://console.cloud.google.com/) で新規プロジェクトを作成します。

| 項目           | 値                     |
| -------------- | ---------------------- |
| プロジェクト名 | `mcp-server-workspace` |

## 2. API の有効化

1. 上部のプロジェクト選択から **mcp-server-workspace** を選択
2. 「APIとサービス」 > 「有効なAPIとサービス」 へ移動
3. 「APIとサービスの有効化」ボタンをクリック
4. 以下のAPIを検索して有効化します：

![APIの有効化](./images/enable-apis.png)

- ✅ Google Sheets API
- ✅ Google Slides API
- ✅ Google Drive API
- ✅ Google Docs API

## 3. OAuth 同意画面の設定

メニューから「OAuth 同意画面」 を選択し、以下の情報を入力します。

**① アプリ情報**

| 項目                   | 値                                |
| ---------------------- | --------------------------------- |
| アプリ名               | `MCP Server for Google Workspace` |
| ユーザーサポートメール | 自分のメールアドレス              |

→ 「次へ」をクリック

**② 対象**

| 項目 | 値                                           |
| ---- | -------------------------------------------- |
| 対象 | `内部` または `外部`（下記の使い分けを参照） |

- **`内部`**: Google Workspace 組織のアカウントだけで使う場合。組織外のアカウントは認可できません
- **`外部`**: 個人の Google アカウントで使う場合。個人アカウントで作ったプロジェクトでは `内部` は選択できません

→ 「次へ」をクリック

**⚠️ `外部` を選んだ場合は、公開ステータスを「テスト中」のままにし、テストユーザーを登録してください**

このサーバーは **機密スコープ**（`spreadsheets` / `documents` / `presentations`）を要求します。
そのため、**Google の審査を通さずに公開ステータスを `本番` にすると、認可が完全にブロックされます。**

```
アクセスをブロック: <アプリ名> は Google の審査プロセスを完了していません
```

このブロックには回避手段がありません。次の設定にしてください。

| 公開ステータス     | 未審査アプリの挙動                                                             |
| ------------------ | ------------------------------------------------------------------------------ |
| `テスト中`         | 登録済みテストユーザーのみ認可可。警告は出るが「詳細」→「移動」で通過できる ✅ |
| `本番`（未審査）   | **アクセスをブロック。通過手段なし** ❌                                        |
| `本番`（審査済み） | 誰でも認可可（審査には数週間かかる）                                           |

**手順**: 「対象」画面の **テストユーザー** セクションで「+ Add users」をクリックし、
このアプリを使う Google アカウントのアドレスを追加します。

認可時に「Google はこのアプリを確認していません」と表示されたら、
**「詳細」→「（安全でないページ）に移動」** で進めてください。

> **⚠️ テスト中は refresh token が 7 日で失効します**
>
> 出典: [Google Identity - Refresh token expiration](https://developers.google.com/identity/protocols/oauth2#expiration)
> 「外部ユーザータイプかつ公開ステータスが Testing のプロジェクトには、7 日で失効する refresh token が発行される」
>
> 7 日ごとに次のコマンドで再認可してください。
>
> ```sh
> npm run setup -- --account <ラベル> --force
> ```
>
> 恒久的に解消するには Google の審査申請が必要です（ホームページ・プライバシーポリシー・デモ動画の提出）。
> なお `内部` のプロジェクトは審査対象外のため、この制限を受けません。

**③ 連絡先情報**

| 項目           | 値                   |
| -------------- | -------------------- |
| メールアドレス | 自分のメールアドレス |

## 4. OAuth クライアントを作成

1. 「認証情報」メニューから「認証情報を作成」をクリック
2. 「OAuth クライアント ID」を選択

| 項目                   | 値                        |
| ---------------------- | ------------------------- |
| アプリケーションの種類 | `デスクトップアプリ`      |
| 名前                   | `MCP Server OAuth Client` |

3. 「作成」ボタンをクリック
4. クライアント ID とクライアント シークレットが表示されます
5. **「JSON をダウンロード」** し、ファイル名を `credentials.json` に変更

> **重要**: この `credentials.json` ファイルは次のステップで使用します。
>
> - **共有クライアントとして使う場合**: `~/.google-workspace-mcp/credentials.json`
> - **特定のアカウント専用にする場合**: `~/.google-workspace-mcp/accounts/<ラベル>/credentials.json`

## サービスアカウントを作成する

ブラウザでの認可・同意画面・審査がすべて不要になる方式です。

> **どのアカウントで作業するか**
>
> 使いたい Google アカウント（例: 個人アカウント）で Cloud Console にログインしてください。
> 別のアカウントのセッションが残っていると、意図しないプロジェクトに作られます。
> **シークレットウィンドウ**を使うと確実です。

### 1. プロジェクトと API の準備

[1. プロジェクト作成](#1-プロジェクト作成) と [2. API の有効化](#2-api-の有効化) は OAuth の場合と同じです。
**[3. OAuth 同意画面の設定](#3-oauth-同意画面の設定) 以降は不要です。**

有効化されているかは、次の URL で確認できます（`PROJECT_ID` は自分のプロジェクト ID に置き換え）。

```
https://console.cloud.google.com/apis/dashboard?project=PROJECT_ID
```

Sheets / Slides / Drive / Docs の 4 つが「有効な API とサービス」に並んでいれば OK です。

### 2. サービスアカウントを作成

作成画面へは次の URL で直接行けます。

```
https://console.cloud.google.com/iam-admin/serviceaccounts/create?project=PROJECT_ID
```

メニューから辿る場合: **「IAM と管理」** > **「サービス アカウント」** > **「+ サービス アカウントを作成」**

**① サービス アカウントの詳細**

| 項目                   | 入力                                        |
| ---------------------- | ------------------------------------------- |
| サービス アカウント名  | `mcp-bot`（任意の名前で構いません）         |
| サービス アカウント ID | 名前から自動生成されます。**そのままで OK** |
| 説明                   | 空欄で OK                                   |

→ **「完了」** をクリック

> **⚠️ ここが最もつまずきやすい箇所です**
>
> **「作成して続行」ではなく「完了」を押してください。**
> 「作成して続行」はロール（権限）の選択画面に進みますが、**ロールは一切不要**です。
> Drive のアクセス権は IAM ロールではなく、**ファイルの共有設定**だけで決まります。
>
> 公式ドキュメントでも「Granting roles and setting access controls are entirely optional」と明記されています。
> 出典: [Create service accounts | IAM](https://docs.cloud.google.com/iam/docs/service-accounts-create)
>
> 誤って「作成して続行」を押した場合も、ロールを何も選ばずに「続行」→「完了」で問題ありません。

### 3. 鍵をダウンロード

1. 作成されたサービスアカウントの一覧で、**メールアドレス**（`mcp-bot@PROJECT_ID.iam.gserviceaccount.com` の形）を**クリック**
2. 上部の **「キー」** タブを開く
3. **「鍵を追加」** > **「新しい鍵を作成」**
4. キーのタイプで **「JSON」** を選択
5. **「作成」** をクリック

JSON ファイルが自動的にダウンロードされます（通常は `~/Downloads/`）。

> **この鍵は再ダウンロードできません。** 紛失した場合は新しい鍵を作り直してください。
> パスワードと同等の機密情報です。リポジトリにコミットしたり、他人に渡したりしないでください。

> **「鍵の作成がブロックされました」と表示された場合**
>
> 組織ポリシー `iam.disableServiceAccountKeyCreation` が有効になっています。
> 2024 年 5 月 3 日以降に作成された組織では既定で有効です。
> 個人アカウントのプロジェクトは組織に属さないため通常は発生しませんが、
> 会社の組織配下のプロジェクトでは管理者による除外設定が必要です。
> 出典: [Create and delete service account keys | IAM](https://docs.cloud.google.com/iam/docs/keys-create-delete)

### 4. サーバーに登録する

ダウンロードしたファイル名を確認します。

```sh
ls -t ~/Downloads/*.json | head -3
```

登録します。**ブラウザは開きません。**

```sh
npm run setup -- --account private \
  --description "個人の Google アカウント" \
  --service-account ~/Downloads/<ダウンロードした鍵>.json
```

完了すると、共有先のアドレスが表示されます。

```
⚠️  最後に、使いたいファイルを共有してください:

     mcp-bot@your-project.iam.gserviceaccount.com
```

鍵を差し替える場合は `--force` を付けて再実行してください。

### 5. ファイルを共有する

**この手順を忘れると、サービスアカウントは何も見えません。**

1. [Google ドライブ](https://drive.google.com/) を、そのアカウントで開く
2. フォルダを作る（例: `MCP共有`）
3. フォルダを右クリック > **「共有」** > 手順 4 で表示されたアドレスを貼り付け > 権限を **「編集者」** > 送信
4. AI に読み書きさせたいファイルを、そのフォルダに移動する

以降、そのフォルダに入れたファイルは自動的に読み書きできます。ファイルを追加するたびに共有し直す必要はありません。

> 共有時に通知メールに関する警告が出ることがありますが、サービスアカウントはメールを受け取れないだけなので、そのまま共有して問題ありません。

### 6. 動作を確認する

共有が効いているかは、`accounts_list` で登録を確認したうえで、
共有したファイルを AI に読ませてみるのが確実です。

```
GitHub Copilot: private アカウントで、共有フォルダにあるドキュメントを読んで
```

**「The caller does not have permission」** と出る場合は、次を確認してください。

| 症状                             | 原因                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| 共有したはずのファイルが見えない | 共有先アドレスの綴り違い、または共有先が別のサービスアカウント |
| 一部のファイルだけ見えない       | そのファイルが共有フォルダの外にある                           |
| すべて権限エラー                 | `account` の指定違い（別のアカウントで実行している）           |
| `DECODER routines` エラー        | 鍵ファイルが壊れている。鍵を作り直す                           |

### 制約

> **サービスアカウントは新規ファイルを作成できません。**
> サービスアカウントはストレージ容量を持たずファイルを所有できないため、
> 作成しようとすると `storageQuotaExceeded` エラーになります。
> 出典: [Create and populate folders | Google Drive](https://developers.google.com/workspace/drive/api/guides/create-file)
>
> 新規作成も必要な場合は、そのアカウントは OAuth で登録してください。
> アカウントごとに方式を選べるので、両方を別ラベルで併用することもできます。
